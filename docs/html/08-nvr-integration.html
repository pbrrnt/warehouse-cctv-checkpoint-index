การเชื่อมต่อกับ NVR และการซิงก์เวลา

ระบบนี้ไม่ได้แทนที่ NVR — NVR ยังเป็นตัวบันทึกวิดีโอหลัก หน้าที่ของเราคือบอกว่า "ไปดูที่กล้องไหน เวลาไหน" แล้วเจ้าหน้าที่ไปเปิดของจริงใน NVR

1. ★ ทำไมเรื่องเวลาถึงสำคัญที่สุด

ผลการค้นหาของเรามีค่า ก็ต่อเมื่อ เจ้าหน้าที่เอา timestamp ไปเปิดใน NVR แล้วเจอภาพนั้นจริง

ระบบเราบอก:  "กล้องประตูใหญ่ 14:32:07 น."
เจ้าหน้าที่เปิด NVR ช่อง 3 ที่ 14:32:07  →  ต้องเห็นรถคันนั้น

ถ้าเวลาเพี้ยน 30 วินาที เจ้าหน้าที่จะเปิดไปแล้วไม่เจอ → เลิกใช้ระบบภายในสัปดาห์แรก เรื่องนี้ไม่ใช่ nice-to-have แต่เป็นเงื่อนไขที่ทำให้ระบบมีค่าหรือไม่มีค่าเลย

เกณฑ์: ส่วนต่างเวลาระหว่าง กล้อง ↔ NVR ↔ เครื่อง Frigate ต้อง < 2 วินาที ตลอดเวลา

2. สถาปัตยกรรมเวลา

            ┌─────────────────────────┐
            │  NTP Server ตัวเดียว     │
            │  (แนะนำ: NVR เป็นตัวจ่าย  │
            │   หรือ router ในไซต์)    │
            └────┬────────┬────────┬───┘
                 │        │        │
         ┌───────▼──┐  ┌──▼───┐  ┌─▼──────────┐
         │ กล้องทุกตัว│  │ NVR  │  │ เครื่อง     │
         │           │  │      │  │ Frigate/DB │
         └───────────┘  └──────┘  └────────────┘

หลักการ: ทุกอุปกรณ์ในไซต์ซิงก์กับ NTP source เดียวกัน ห้ามให้กล้องบางตัวชี้ time.windows.com ส่วน NVR ชี้ pool.ntp.org เพราะแม้ทั้งคู่จะ "ถูก" แต่ความหน่วงของเน็ตอาจทำให้ต่างกันได้

2.1 ถ้าไซต์ไม่มีอินเทอร์เน็ต

ตั้งเครื่อง Frigate เป็น NTP server ในวง LAN แล้วให้ NVR และกล้องชี้มาที่เครื่องนี้ (ติดตั้ง chrony แล้วเปิด allow สำหรับ subnet ของไซต์ — ดูขั้นตอนใน 09-multi-site-runbook.md)

3. การตั้งค่าแต่ละอุปกรณ์

3.1 เครื่อง Frigate (Debian/Ubuntu)

sudo timedatectl set-timezone Asia/Bangkok

timedatectl status

ต้องเห็น System clock synchronized: yes และ NTP service: active

3.2 NVR Dahua

Setup → System → General → Date & Time

ค่า ตั้งเป็น
Time Zone GMT+07:00
NTP เปิด
Server IP ของ NTP source ที่เลือก
Update Period 10 นาที
DST ปิด (ประเทศไทยไม่มี DST)

Dahua NVR ส่วนใหญ่มีปุ่ม "Sync with NVR" ในหน้าจัดการกล้อง ซึ่งจะดันเวลาไปให้กล้องทุกตัว — ใช้ปุ่มนี้ เป็นวิธีที่ง่ายและเชื่อถือได้ที่สุด

3.3 กล้อง

  • กล้อง Dahua ที่ต่อกับ NVR Dahua: ใช้ "Sync with NVR" ตามข้อบน
  • กล้องจีน ONVIF ทั่วไป: เข้าหน้าเว็บของกล้องแล้วตั้ง NTP เอง (Configuration → System → Time Settings) — ตำแหน่งเมนูต่างกันไปตามยี่ห้อ
  • กล้องบางรุ่นตั้ง NTP ไม่ได้เลย → บันทึกไว้แล้วชดเชยด้วย clock_offset_ms (หัวข้อ 4)

3.4 ★ ปิดการแสดงเวลาบนภาพ (OSD) หรือย้ายตำแหน่ง

ถ้ากล้องซ้อนข้อความเวลาลงบนภาพ (OSD timestamp) อย่าให้ทับโซนป้ายทะเบียนหรือใบหน้า เพราะจะทำให้ OCR อ่านผิด ทางที่ดีที่สุดคือปิด OSD ไปเลย เพราะเรามี timestamp จากระบบอยู่แล้ว

4. นโยบายการเก็บเวลาในระบบ

จุด รูปแบบ
ในฐานข้อมูล UTC เสมอ (TIMESTAMPTZ)
ใน API ISO 8601 พร้อม offset
ในหน้าจอผู้ใช้ Asia/Bangkok พร้อมวินาที เช่น 03/08/2569 14:32:07
ในผลที่ให้ไปเปิด NVR เวลาท้องถิ่นระดับวินาที + ปุ่มคัดลอก

4.1 clock_offset_ms — การชดเชยกล้องที่แก้ไม่ได้

ตาราง cameras มีคอลัมน์ clock_offset_ms สำหรับกล้องที่เวลาเพี้ยนถาวรและตั้ง NTP ไม่ได้

เวลาที่แสดงให้ผู้ใช้ = เวลาที่ระบบบันทึก + clock_offset_ms

วิธีหาค่า: ถ่ายภาพนาฬิกาที่แม่นยำ (เช่น หน้าจอมือถือที่ซิงก์แล้ว) ผ่านหน้ากล้อง แล้วเทียบกับ timestamp ที่ระบบบันทึก ทำซ้ำ 3 ครั้งแล้วใช้ค่ากลาง บันทึกวันที่วัดไว้ด้วย เพราะค่า offset ของกล้องราคาถูกอาจเลื่อนไปตามเวลา

5. การ map กล้อง ↔ ช่อง NVR

นี่คือข้อมูลที่ทำให้ผลการค้นหาใช้งานได้จริง ถ้าเจ้าหน้าที่ไม่รู้ว่ากล้อง WH01-GATE-LPR คือช่องไหนใน NVR ก็ไปเปิดต่อไม่ได้

บันทึกในตาราง cameras:

คอลัมน์ ตัวอย่าง ใช้ทำอะไร
id WH01-GATE-LPR รหัสในระบบเรา
name ประตูใหญ่ - อ่านป้าย ชื่อที่ผู้ใช้เห็น
nvr_channel 3 ช่องที่ต้องเปิดใน NVR
role lpr บทบาทที่จุดคอขวด
clock_offset_ms 0 ค่าชดเชยเวลา

หน้าผลการค้นหาต้องแสดงครบทั้ง 3 อย่าง: ชื่อกล้อง + ช่อง NVR + เวลาระดับวินาที

6. ขั้นตอนการใช้งานจริงของเจ้าหน้าที่

1. เปิดหน้าเว็บระบบดัชนี (ในวง LAN ของโกดัง)

2. ค้นหา เช่น
   • พิมพ์ทะเบียน "1กก1234"  (ระบบค้นแบบ fuzzy อ่านผิด 1-2 ตัวก็ยังเจอ)
   • หรืออัปโหลดรูปหน้าคน
   • หรือกรอง: รถกระบะสีขาว + ประตูใหญ่ + ช่วงเวลา

3. ระบบคืนรายการผลลัพธ์ แต่ละแถวมี:
   ┌────────────────────────────────────────────────────┐
   │ [รูป]  1กก 1234 กรุงเทพมหานคร      ความมั่นใจ 96%   │
   │        กระบะ สีขาว                                  │
   │        ประตูใหญ่ (NVR ช่อง 3)  •  เข้า              │
   │        03/08/2569  14:32:07     [คัดลอกเวลา]        │
   └────────────────────────────────────────────────────┘

4. กด [คัดลอกเวลา] แล้วไปเปิด NVR ช่อง 3 ที่เวลานั้น

5. ดูวิดีโอความละเอียดเต็มจาก NVR ตามปกติ

ระบบเราทำงานที่ยาก (หาเข็มในกองฟาง) ส่วน NVR ทำงานที่ถนัด (เล่นวิดีโอ)

6.1 การเปิดตามเวลาใน NVR Dahua

วิธีเข้า ขั้นตอน
หน้าเว็บ NVR Playback → เลือกช่อง → เลือกวันที่ → พิมพ์เวลาในช่อง time → Play
SmartPSS / DSS Playback → เลือกกล้อง → ลากไทม์ไลน์ หรือพิมพ์เวลา
หน้าจอ NVR โดยตรง คลิกขวา → Playback → เลือกช่องและเวลา

แนะนำ: เผื่อเวลาย้อนหลัง 5–10 วินาทีจาก timestamp ที่ระบบให้ เพราะระบบบันทึกตอนที่ตรวจพบวัตถุ ซึ่งรถอาจเข้ามาในเฟรมก่อนหน้านั้นเล็กน้อย

7. การตรวจสุขภาพเวลา (Time Sync Health Check)

7.1 สคริปต์ scripts/check_time_sync.py (จะเขียนในเฟส 2)

สิ่งที่สคริปต์ต้องทำ:

  1. อ่านเวลาของเครื่องตัวเอง (แหล่งอ้างอิง)
  2. ดึงเวลาจาก NVR — ผ่าน ONVIF GetSystemDateAndTime หรือ HTTP API ของ NVR
  3. ดึงเวลาจากกล้องทุกตัวใน cameras — ผ่าน ONVIF GetSystemDateAndTime
  4. คำนวณส่วนต่าง หักลบ network round-trip ออกก่อน
  5. รายงานผลเป็นตาราง และ exit code ≠ 0 ถ้ามีอุปกรณ์ใดต่างเกิน 2 วินาที
  6. เขียนผลลง audit_log เพื่อดูแนวโน้มย้อนหลัง

ตัวอย่างผลลัพธ์ที่ต้องการ:

อุปกรณ์                    ส่วนต่าง      สถานะ
─────────────────────────────────────────────
NVR (192.168.1.10)         +0.3 วิ       OK
WH01-GATE-LPR              +0.5 วิ       OK
WH01-GATE-OVERVIEW         +0.4 วิ       OK
WH01-DOOR-FACE             +14.2 วิ      ★ เกินเกณฑ์
─────────────────────────────────────────────
สรุป: 1 อุปกรณ์ไม่ผ่านเกณฑ์

7.2 ตารางเวลาการตรวจ

ความถี่ การตรวจ
ทุกวัน 06:00 รันอัตโนมัติผ่าน cron แจ้งเตือนถ้าไม่ผ่าน
ตอนติดตั้งไซต์ใหม่ รันด้วยมือ ต้องผ่านก่อนส่งมอบ
หลังไฟดับ/รีบูต NVR รันด้วยมือ
หลังเปลี่ยน/เพิ่มกล้อง รันด้วยมือ

7.3 เมื่อพบว่าเวลาเพี้ยน

  1. ตรวจว่ากล้อง/NVR ยัง online และตั้ง NTP ไว้ถูก
  2. สั่ง sync ใหม่ (Dahua: ปุ่ม "Sync with NVR")
  3. ถ้ายังเพี้ยน → ตรวจว่า firewall บล็อก NTP (UDP 123) หรือไม่
  4. ถ้ากล้องรุ่นนั้นตั้ง NTP ไม่ได้เลย → วัดค่า offset แล้วบันทึกใน clock_offset_ms
  5. บันทึกลง docs/00-decisions.md ว่าไซต์ไหนมีกล้องที่ต้องชดเชย เพื่อให้คนดูแลรุ่นถัดไปรู้

8. ข้อจำกัดที่ต้องแจ้งผู้ใช้ให้ทราบ

ข้อจำกัด ผลกระทบ
ระบบเห็นเฉพาะจุดคอขวดที่ติดตั้ง ไม่รู้ว่าคน/รถไปไหนต่อภายในโกดัง ต้องตามด้วย NVR เอง
ระบบเก็บดัชนีนานกว่าที่ NVR เก็บวิดีโอ อาจค้นเจอเหตุการณ์ที่วิดีโอใน NVR ถูกลบไปแล้ว — ยังมี snapshot ให้ดู แต่ไม่มีคลิปเต็ม
ทางเข้า–ออกที่ไม่ได้ติดกล้อง เป็นจุดบอดถาวร (ดูรายการที่บันทึกไว้ตอนสำรวจใน 10-chokepoint-design.md)

ข้อสอง สำคัญ: ควรตั้ง retention ของดัชนีให้ ไม่ยาวเกินที่ NVR เก็บมากนัก หรือแสดงคำเตือนในหน้าผลลัพธ์เมื่อเหตุการณ์เก่ากว่าที่ NVR เก็บ เพื่อไม่ให้ผู้ใช้เสียเวลาไปหาวิดีโอที่ไม่มีแล้ว
