## ขั้นที่ 1 — สำรวจหน้างาน (ที่ไซต์, ~4 ชม.)

> **ห้ามสั่งซื้อของก่อนทำขั้นนี้เสร็จ**

### 1.1 สำรวจทางเข้า–ออกทั้งหมด

- [ ] เดินรอบพื้นที่ **ทั้งรอบ** ทำรายการทางเข้า–ออกทุกจุด
- [ ] กรอกตาราง "รายการทางเข้า–ออกทั้งหมด" ใน `10-chokepoint-design.md` หัวข้อ 6.1
- [ ] ถามเจ้าหน้าที่ประจำว่ามีทางลัด/ช่องรั้วที่คนใช้จริงหรือไม่ (มักไม่อยู่ในผัง)
- [ ] ตัดสินใจว่าจะติดจุดไหนบ้าง และ **บันทึกจุดที่ไม่ติดพร้อมเหตุผล**

### 1.2 สำรวจแต่ละจุดคอขวดที่จะติดตั้ง

สำหรับแต่ละจุด กรอกแบบบันทึกใน `10-chokepoint-design.md` หัวข้อ 6.2:

- [ ] วัดระยะที่ติดกล้องได้ และความสูงที่ติดได้
- [ ] ตรวจทิศที่กล้องจะหัน (เลี่ยงตะวันออก/ตะวันตก)
- [ ] วัดความเร็วรถปัจจุบัน และดูว่ามีลูกระนาด/ไม้กั้นอยู่แล้วหรือไม่
- [ ] ตรวจไฟฟ้าและสาย LAN ว่าถึงจุดหรือไม่ ถ้าไม่ วัดระยะที่ต้องเดินเพิ่ม
- [ ] ประเมินกล้องเดิม: ปรับ shutter ล็อก 1/500 ได้ไหม, มีโหมด LPR ไหม
- [ ] **ทดสอบจำนวน RTSP session** — ต่อดูสตรีมพร้อมกัน 2–3 เครื่องขณะ NVR ยังใช้งานอยู่
- [ ] ตรวจ backlight ที่จุดคอขวดคน (ยืนที่ตำแหน่งคนเดินแล้วมองไปทางกล้อง)

### 1.3 สำรวจ NVR และเครือข่าย

- [ ] บันทึกยี่ห้อ/รุ่น NVR, IP, บัญชีที่ใช้เข้าดู
- [ ] บันทึกว่า NVR เก็บวิดีโอย้อนหลังกี่วัน
- [ ] บันทึกช่อง (channel) ของกล้องแต่ละตัว
- [ ] ตรวจว่าไซต์มีอินเทอร์เน็ตหรือไม่ (มีผลกับ NTP และการอัปเดต)
- [ ] จด subnet ของวง LAN และดูว่ามี IP ว่างสำหรับเครื่องใหม่
- [ ] ตรวจว่ามีปลั๊กไฟและพื้นที่วางมินิพีซี (ควรอยู่ในตู้ Rack หรือห้องที่มีแอร์)

### 1.4 สรุปผลสำรวจ

- [ ] สรุปว่าต้องซื้อกล้องใหม่กี่ตัว ไฟกี่ชุด ต้องทำลูกระนาดหรือไม่
- [ ] ประเมินงบตามตารางใน `10-chokepoint-design.md` หัวข้อ 9
- [ ] ส่งสรุปให้ผู้อนุมัติ

## ขั้นที่ 2 — จัดซื้อ (~1–3 สัปดาห์)

- [ ] มินิพีซี — ดูทางเลือกและเกณฑ์ใน `02-hardware-sizing.md` หัวข้อ 1:
      **แนะนำ** Micro/Tiny มือสอง ซีพียูรุ่นลงท้าย T (เช่น i5-8500T) + SSD เพิ่ม
      หรือ N100/N305 ใหม่ถ้าไม่อยากยุ่งกับของมือสอง
  - [ ] ถ้าซื้อมือสอง: ตรวจรุ่นซีพียูว่า **ไม่ใช่รุ่นที่ไม่มี AVX2** (ดูตารางห้ามซื้อใน `02-hardware-sizing.md` หัวข้อ 1.3) และผ่านเช็กลิสต์หัวข้อ 1.5 ก่อนโอนเงิน
- [ ] กล้อง LPR (1080p เซนเซอร์ ≥1/1.8", varifocal, ล็อก shutter ได้, มีโหมด LPR)
- [ ] กล้อง overview (ถ้าไม่ใช้ของเดิม)
- [ ] กล้องใบหน้า (ถ้าไม่ใช้ของเดิม)
- [ ] IR illuminator 850nm และ/หรือ ไฟ LED ขาว
- [ ] อุปกรณ์เดินสาย PoE switch สาย LAN
- [ ] ลูกระนาด (ถ้าต้องทำเพิ่ม)

> **อย่าลดสเปกกล้อง LPR เพื่อประหยัด** — ดูเหตุผลใน `10-chokepoint-design.md` หัวข้อ 9
> เครื่องประมวลผลคือจุดที่ประหยัดได้จริงโดยไม่กระทบความแม่นยำ — ย้ายส่วนต่างไปลงกล้อง LPR แทน

## ขั้นที่ 3 — งานติดตั้งหน้างาน (ที่ไซต์, ~1–2 วัน)

### 3.1 งานโยธาและไฟฟ้า

- [ ] ติดตั้งลูกระนาด **ห่างจากโซนถ่ายภาพ 5–10 เมตร**
- [ ] ตีเส้นบนพื้นกำหนดโซนถ่ายภาพให้เห็นชัด
- [ ] เดินไฟฟ้าและสาย LAN ถึงจุดกล้องและจุดไฟส่องสว่าง
- [ ] ติดตั้ง PoE switch

### 3.2 ติดตั้งกล้อง LPR

- [ ] ติดที่ความสูง **1.0–1.5 ม.** (ไม่ใช่ 3–4 ม. ตามความเคยชิน)
- [ ] **หันจับท้ายรถ** เพื่อให้ได้ป้ายมอเตอร์ไซค์ด้วย
- [ ] ปรับมุมเบี่ยงแนวนอน ≤ 30° และแนวดิ่ง ≤ 30°
- [ ] ปรับ zoom ให้ความกว้างภาพที่ระนาบป้าย ≤ 3.2 ม. (สำหรับ 1080p)
- [ ] ตั้งค่ากล้องตาม `10-chokepoint-design.md` หัวข้อ 3.8:
  - [ ] **ล็อก shutter 1/500s** (ห้าม auto)
  - [ ] จำกัด gain สูงสุด ~50
  - [ ] เปิด WDR
  - [ ] ลด/ปิด 3D DNR
  - [ ] bitrate substream ≥ 4 Mbps, codec H.264
  - [ ] ปิดเสียง
  - [ ] ปิด OSD timestamp หรือย้ายไม่ให้ทับโซนป้าย

### 3.3 ติดตั้งกล้อง overview และกล้องใบหน้า

- [ ] กล้อง overview: FOV กว้าง **ภาพสี ห้ามเปิด IR**
- [ ] กล้องใบหน้า: สูง **1.6–1.8 ม.** มุมก้ม ≤ 15° ระยะจับภาพ 1.5–3 ม.
- [ ] ตรวจว่าไม่มี backlight ด้านหลังคน

### 3.4 ติดตั้งไฟส่องสว่าง

- [ ] เล็งไม่ให้แสงเข้าเลนส์กล้องโดยตรง
- [ ] เล็งไม่ให้แยงตาคนขับ
- [ ] ตรวจว่าแสงตกบนโซนถ่ายภาพสม่ำเสมอ

### 3.5 ตั้ง IP และตั้งชื่อ

- [ ] ตั้ง **IP แบบคงที่** ให้กล้องทุกตัวและมินิพีซี (ห้ามใช้ DHCP)
- [ ] ตั้งชื่อกล้องตามรูปแบบ: `<SITE_ID>-<จุด>-<บทบาท>`
  - ตัวอย่าง: `WH01-GATE-LPR`, `WH01-GATE-OVERVIEW`, `WH01-DOOR-FACE`
- [ ] บันทึก IP / บัญชี / รหัสผ่าน ลงในเอกสารส่งมอบ (**ห้ามใส่ใน git**)

## ขั้นที่ 4 — ตรวจรับงานติดตั้ง (ที่ไซต์)

> **ต้องผ่านทุกข้อก่อนไปขั้นที่ 5** ถ้าไม่ผ่าน กลับไปแก้การติดตั้ง

ใช้เช็กลิสต์เต็มจาก [`10-chokepoint-design.md`](10-chokepoint-design.md) หัวข้อ 7

### 4.1 ทดสอบกลางวัน
- [ ] รถยนต์ 20 คัน — ตัวอักษรบนป้าย ≥ 25 px ทุกคัน
- [ ] มอเตอร์ไซค์ 20 คัน — ตัวอักษร ≥ 25 px ทุกคัน
- [ ] ป้ายอยู่ในเฟรมเต็มใบ ทั้งรถสูงและรถเตี้ย
- [ ] ทดสอบซ้ำตอน 07:00 และ 17:00 (แสงอาทิตย์แยง)
- [ ] ความเร็วรถผ่านโซนถ่ายภาพ ≤ 10 km/h

### 4.2 ★ ทดสอบกลางคืน (ห้ามข้าม)
- [ ] รถ 20 คันหลัง 20:00 น. — อ่านป้ายด้วยตาเปล่าได้ ≥ 19 คัน
- [ ] ทดสอบมอเตอร์ไซค์กลางคืนแยกต่างหาก
- [ ] ไฟหน้ารถไม่ทำป้ายขาวโพลน (ทดสอบกับรถเปิดไฟสูง)
- [ ] กล้องไม่สลับเป็น shutter ช้าอัตโนมัติตอนมืด

### 4.3 ทดสอบใบหน้า
- [ ] ระยะห่างระหว่างตา ≥ 60 px
- [ ] ไม่มี backlight ทั้งกลางวันและกลางคืน

### 4.4 เก็บชุดภาพตัวอย่าง
- [ ] เก็บภาพทดสอบไว้ที่ `samples/<SITE_ID>/day/` และ `samples/<SITE_ID>/night/`
- [ ] **ห้ามลบ** — จะใช้เป็น ground truth วัดความแม่นของ LPR

## ขั้นที่ 5 — ติดตั้งซอฟต์แวร์ (~2 ชม.)

### 5.1 เตรียมเครื่อง

- [ ] ติดตั้ง Debian 12 หรือ Ubuntu 24.04 LTS
- [ ] ตั้ง timezone:

```bash
sudo timedatectl set-timezone Asia/Bangkok
```

- [ ] ติดตั้ง Docker และ Docker Compose:

```bash
curl -fsSL https://get.docker.com | sudo sh
```

- [ ] เพิ่มผู้ใช้เข้ากลุ่ม docker และ render (สำหรับ iGPU):

```bash
sudo usermod -aG docker,render,video $USER
```

- [ ] ออกจากระบบแล้วเข้าใหม่ จากนั้นตรวจว่าเห็น iGPU:

```bash
ls -l /dev/dri
```

ต้องเห็น `renderD128` ถ้าไม่เห็น แปลว่า driver Intel ยังไม่พร้อม

### 5.2 ตั้ง NTP

- [ ] **ถ้าไซต์มีอินเทอร์เน็ต**: ตรวจว่า `timedatectl status` แสดง `System clock synchronized: yes`
- [ ] **ถ้าไซต์ไม่มีอินเทอร์เน็ต**: ตั้งเครื่องนี้เป็น NTP server

```bash
sudo apt install -y chrony
```

  แล้วเพิ่มบรรทัด `allow 192.168.1.0/24` (แก้เป็น subnet จริงของไซต์) ใน `/etc/chrony/chrony.conf` แล้วรีสตาร์ต:

```bash
sudo systemctl restart chrony
```

- [ ] ตั้ง NTP ใน NVR ชี้มาที่ NTP source ที่เลือก (ดู [`08-nvr-integration.md`](08-nvr-integration.md) หัวข้อ 3.2)
- [ ] สั่ง NVR "Sync with NVR" เพื่อดันเวลาไปให้กล้องทุกตัว
- [ ] ตั้ง NTP ในกล้อง ONVIF ที่ไม่ได้ต่อกับ NVR Dahua เอง

### 5.3 ติดตั้งระบบ

- [ ] คัดลอกโปรเจกต์ลงเครื่อง
- [ ] คัดลอก `.env.example` เป็น `.env` แล้วแก้ค่า:
  - [ ] `SITE_ID` และ `SITE_NAME`
  - [ ] รหัสผ่านฐานข้อมูล (สุ่มใหม่ทุกไซต์)
  - [ ] บัญชี/รหัสผ่านกล้อง (**URL-encode อักขระพิเศษ** `@` `:` `/` `#`)
  - [ ] IP ของ NVR
  - [ ] **ห้ามแก้เวอร์ชันที่ปักหมุดไว้** — ทุกไซต์ต้องรันเวอร์ชันเดียวกัน
- [ ] แก้ `frigate/config.yml` ใส่ RTSP URL และโซนของกล้องจริง
- [ ] ตรวจไวยากรณ์ก่อนสตาร์ต:

```bash
docker compose config
```

- [ ] สตาร์ต**เฉพาะ infrastructure ก่อน** (frigate, mosquitto, postgres, redis — ยังไม่ใช่ indexer/api/web):

```bash
docker compose up -d
```

- [ ] รอ postgres พร้อม (`docker compose ps` เห็น `healthy`) แล้ว**สร้างตาราง** (ยังไม่มีใครสร้างให้อัตโนมัติ):

```bash
pip install -r services/common/requirements.txt requests   # sqlalchemy/alembic/pgvector/psycopg + requests (check_time_sync.py) บนเครื่อง host
cd db
DATABASE_URL="postgresql+psycopg://<user>:<pass>@localhost:<POSTGRES_PORT>/<db>" python -m alembic upgrade head
cd ..
```

- [ ] **★ ห้ามข้าม — ใส่ข้อมูลไซต์+กล้องลง DB** (ไม่มีขั้นนี้ = `worker.py` จะเจอ "ไม่รู้จักกล้อง" แล้วข้ามทุก event เงียบ ๆ ไม่มี error ให้เห็น ดูเหมือนระบบทำงานปกติทั้งที่ไม่มีข้อมูลออกมาเลย):

```bash
cp scripts/site_config.example.json site_config.json   # แก้ site/cameras ให้ตรงกับไซต์จริง (nvr_channel, zone_config ฯลฯ)
python scripts/seed_site.py --config site_config.json --database-url "postgresql+psycopg://<user>:<pass>@localhost:<POSTGRES_PORT>/<db>"
```

- [ ] **ดาวน์โหลดไฟล์โมเดล AI** (ไม่ได้อยู่ใน git — ดู `docs/11-testing.md`):

```bash
python scripts/fetch_models.py
```

- [ ] **สร้าง self-signed cert สำหรับหน้าเว็บ** (ดู ADR-025) — ใส่ IP เครื่องในวง LAN + Tailscale hostname เป็น SAN ให้ครบ:

```bash
scripts/gen_selfsigned_cert.sh "$DATA_ROOT/certs" <ip-เครื่องใน-LAN> <tailscale-hostname>
# ตัวอย่าง: scripts/gen_selfsigned_cert.sh /data/certs 192.168.1.20 wh01-index.tailXXXX.ts.net
```

- [ ] (แนะนำ) ติดตั้ง `$DATA_ROOT/certs/web.crt` เป็น trusted certificate ในเครื่อง 2-3 เครื่องที่เจ้าหน้าที่ใช้ค้นหาประจำ — ไม่งั้น browser จะขึ้นคำเตือน "ไม่ปลอดภัย" ทุกครั้ง (ปกติของ self-signed กดผ่านได้ แต่ติดตั้งครั้งเดียวจะไม่เตือนอีก)

- [ ] สตาร์ตระบบส่วนที่เหลือ (indexer, api, web) — **ต้องมี `--profile app`** ไม่งั้นจะสตาร์ตแค่ infra เหมือนเดิม:

```bash
docker compose --profile app up -d
```

- [ ] ดู log ว่าไม่มี error (ทั้ง Docker และไฟล์ที่อยู่ทนกว่าใน `${DATA_ROOT}/logs/` — ดู `07-operations.md` หัวข้อ 2.4):

```bash
docker compose logs -f --tail=100
```

## ขั้นที่ 6 — ตรวจรับระบบ

### 6.1 ตรวจการเชื่อมต่อกล้อง

- [ ] สำรวจกล้องด้วยสคริปต์:

```bash
python scripts/probe_cameras.py
```

- [ ] ทุกกล้องขึ้น `OK` มี substream และ fps ตรงตามที่ตั้ง

### 6.2 ★ ตรวจการซิงก์เวลา

- [ ] รัน (ใช้ `site_config.json` ตัวเดียวกับตอน seed — ต้องมีฟิลด์ `ip` ต่อกล้องด้วย):

```bash
python scripts/check_time_sync.py --config site_config.json --database-url "$DATABASE_URL"
```

- [ ] **ทุกอุปกรณ์ต่างกัน < 2 วินาที** ถ้าไม่ผ่าน แก้ตาม `08-nvr-integration.md` หัวข้อ 7.3
- [ ] ถ้าอุปกรณ์ไหนตอบ ERROR (ไม่ใช่แค่เกินเกณฑ์) — เช็คว่ารองรับ ONVIF จริงไหมก่อน (`--single <ip>` ทดสอบทีละตัว) กล้อง/NVR บางรุ่นอาจต้องเปิด ONVIF ในเมนูตั้งค่าก่อนถึงจะตอบ

### 6.3 ตรวจสมรรถนะ Frigate

- [ ] เปิด `http://<ip-เครื่อง>:5000` เห็นภาพสดทุกกล้อง
- [ ] ตรวจ `http://<ip-เครื่อง>:5000/api/stats`:
  - [ ] `inference_speed` < 25 ms
  - [ ] `camera_fps` ตรงกับที่ตั้งไว้
  - [ ] **`skipped_fps` = 0** (ถ้าไม่ใช่ แปลว่าเครื่องไม่ไหว)
- [ ] ปล่อยทิ้งไว้ 24 ชม. แล้วตรวจซ้ำ — RTSP ต้องไม่หลุด

### 6.4 ★★ ตรวจ end-to-end กับคนจริง

> **ข้อนี้สำคัญที่สุด ถ้าไม่ผ่าน ระบบไม่มีค่า**

- [ ] ให้เจ้าหน้าที่เลือกเหตุการณ์ที่รู้คำตอบอยู่แล้ว (เช่น รถของตัวเองที่เข้ามาเมื่อเช้า)
- [ ] ค้นในระบบ → ได้ผลลัพธ์พร้อมกล้อง ช่อง NVR และเวลา
- [ ] **เอาเวลานั้นไปเปิดใน NVR แล้วต้องเจอภาพนั้นจริง**
- [ ] ทำซ้ำ 5 เหตุการณ์ ต้องผ่านทั้ง 5

## ขั้นที่ 7 — ส่งมอบและอบรม (~2 ชม.)

- [ ] อบรมเจ้าหน้าที่ใช้หน้าค้นหา (ดูขั้นตอนใน `08-nvr-integration.md` หัวข้อ 6)
- [ ] สอนวิธีเอา timestamp ไปเปิดใน NVR
- [ ] **แจ้งข้อจำกัดให้ชัดเจน**:
  - [ ] ระบบเห็นเฉพาะจุดคอขวดที่ติดตั้ง ไม่เห็นภายในโกดัง
  - [ ] แจ้งรายการทางเข้า–ออกที่ **ไม่ได้** ติดตั้ง (จุดบอด)
  - [ ] ระบบช่วยจำกัดวงค้นหา ไม่ใช่หลักฐานเด็ดขาด ต้องยืนยันด้วยวิดีโอจาก NVR เสมอ
- [ ] ติดตั้ง **ป้ายแจ้งเตือนการเก็บภาพและข้อมูลใบหน้า** ที่จุดคอขวดทุกจุด (ข้อบังคับ PDPA — ดู [`06-pdpa-compliance.md`](06-pdpa-compliance.md))
- [ ] ส่งมอบเอกสาร: IP/บัญชี, ผังกล้อง, ตาราง map ช่อง NVR, เช็กลิสต์ที่ติ๊กแล้ว
- [ ] ตั้ง cron ตรวจเวลาและสำรองข้อมูลรายวัน (ดู [`07-operations.md`](07-operations.md))

## หมายเหตุสำหรับการขยายหลายไซต์

### ทุกไซต์ต้องเหมือนกัน

- [ ] **ปักหมุดเวอร์ชันทุกอย่างใน `.env`** (Frigate tag/digest, เวอร์ชันโมเดล)
- [ ] ห้ามแก้ `docker-compose.yml` หรือโค้ดเฉพาะไซต์ใดไซต์หนึ่ง — ถ้าจำเป็นต้องต่าง ให้ทำผ่าน `.env`
- [ ] ถ้าเจอปัญหาที่ไซต์หนึ่ง **แก้ที่ต้นทางแล้ว roll out ให้ทุกไซต์** อย่าแก้เฉพาะที่

### ตั้งชื่อให้ไม่ซ้ำข้ามไซต์

| สิ่งที่ตั้งชื่อ | รูปแบบ | ตัวอย่าง |
|---|---|---|
| ไซต์ | `WH` + เลข 2 หลัก | `WH01` |
| กล้อง | `<SITE_ID>-<จุด>-<บทบาท>` | `WH01-GATE-LPR` |

### บันทึกความรู้กลับเข้าเอกสาร

หลังเปิดไซต์ใหม่แต่ละครั้ง:
- [ ] จับเวลาว่าแต่ละขั้นใช้เวลาจริงเท่าไร
- [ ] บันทึกปัญหาที่เจอและวิธีแก้ลงใน [`00-decisions.md`](00-decisions.md)
- [ ] **ปรับปรุงเอกสารนี้** ให้ไซต์ถัดไปเร็วขึ้น — เป้าหมายคือไซต์ที่ 3 ต้องเร็วกว่าไซต์ที่ 1 อย่างชัดเจน
