# ระบบดัชนีสืบค้นภาพจากกล้องวงจรปิด

ระบบช่วย **จำกัดวงการค้นหา** สำหรับโกดังที่มี NVR อยู่แล้ว — วิเคราะห์ภาพจากกล้องจุดคอขวด
(ประตูเข้า–ออก) ด้วย AI แล้วทำดัชนีว่า **ใบหน้าแบบนี้ / รถคันนี้ / ทะเบียนนี้ ผ่านเข้า–ออกเมื่อไร**
เพื่อให้เจ้าหน้าที่กระโดดไปยังจุดเวลาที่ถูกต้องใน NVR ได้ทันที แทนการไล่ดูวิดีโอเป็นชั่วโมง

รองรับ **ป้ายทะเบียนภาษาไทย** ซึ่งเป็นสิ่งที่ระบบสำเร็จรูปทั่วไปทำไม่ได้

---

## ระบบนี้คืออะไร (และไม่ใช่อะไร)

| **คือ** | **ไม่ใช่** |
|---|---|
| ดัชนีค้นหาว่าใคร/อะไรผ่านประตูเมื่อไร | ระบบบันทึกวิดีโอ — NVR ทำหน้าที่นั้น |
| เครื่องมือจำกัดวงให้เจ้าหน้าที่ | หลักฐานเด็ดขาด — ต้องยืนยันด้วยวิดีโอเสมอ |
| ดูเฉพาะจุดคอขวดเข้า–ออก | ระบบติดตามทั่วทั้งโกดัง |
| แยกอิสระต่อโกดัง ค้นที่หน้างาน | ระบบรวมศูนย์ (ยังไม่ทำ แต่ไม่ปิดทาง) |

**ตัวอย่างคำถามที่ตอบได้**
- "รถทะเบียน 1กก 1234 เข้ามาวันไหนบ้างเดือนนี้"
- "อัปโหลดรูปหน้าคนนี้ — เคยเข้ามากี่ครั้ง"
- "รถกระบะสีขาวที่เข้าประตูใหญ่บ่ายเมื่อวานมีคันไหน"
- "ตอนนี้มีรถอะไรอยู่ในโกดังบ้าง"

**ตอบไม่ได้:** "คนนั้นเดินไปไหนต่อหลังเข้ามา" — ตามด้วย NVR เอง

---

## ★ หลักการที่ทำให้ระบบนี้ทำงานได้

**1. วิเคราะห์เฉพาะจุดคอขวด ไม่สแกนทุกกล้อง**
ความแม่นยำถูกกำหนดโดย *สภาพภาพ* มากกว่าคุณภาพโมเดล — กล้อง 3 ตัวที่ควบคุมมุม แสง
และความเร็วได้ ให้ผลดีกว่ากล้อง 32 ตัวมุมทั่วไปมาก และทำให้เครื่องราคา ฿8,000 พอใช้

**2. Event-driven ไม่ใช่ frame-driven**
โมเดลหนักทำงานครั้งเดียวต่อ "รถ 1 คัน" ไม่ใช่ทุกเฟรม — ต้นทุน AI ผูกกับจำนวนเหตุการณ์ต่อวัน
(~500 ครั้ง) ไม่ใช่จำนวนกล้อง × fps

**3. NVR เก็บวิดีโอ เราเก็บดัชนี**
ไม่ทำงานซ้ำซ้อน พื้นที่จัดเก็บลดจากระดับ TB เหลือระดับร้อย GB

**4. เวลาต้องตรงกับ NVR < 2 วินาที**
ผลการค้นหามีค่าก็ต่อเมื่อเอา timestamp ไปเปิดใน NVR แล้วเจอภาพจริง — เพี้ยน 30 วินาที = ใช้ไม่ได้

## การติดตั้ง (เฟส 2 เป็นต้นไป)

> ทำตาม [`09-multi-site-runbook.md`](docs/09-multi-site-runbook.md) เป็นหลัก
> ส่วนนี้เป็นสรุปย่อ

### 1. เตรียมเครื่อง

```bash
sudo timedatectl set-timezone Asia/Bangkok
```

```bash
curl -fsSL https://get.docker.com | sudo sh
```

```bash
sudo usermod -aG docker,render,video $USER
```

ออกจากระบบแล้วเข้าใหม่ จากนั้นตรวจว่าเห็น iGPU (ต้องเห็น `renderD128`):

```bash
ls -l /dev/dri
```

### 2. ตั้งค่า

```bash
cp .env.example .env
```

แก้ `.env` — `SITE_ID`, รหัสผ่านฐานข้อมูล, บัญชีกล้อง (**URL-encode อักขระพิเศษ**), IP ของ NVR
แล้วแก้ `frigate/config.yml` ใส่ RTSP URL และวาดโซนตามภาพจริง

### 3. ตรวจไวยากรณ์ก่อนสตาร์ต

```bash
docker compose config
```

### 4. สตาร์ตระบบ

```bash
docker compose up -d
```

เฟส 2 เป็นต้นไป เมื่อมีโค้ดแอปแล้ว:

```bash
docker compose --profile app up -d
```

### 5. ตรวจสอบ

```bash
docker compose logs -f --tail=100
```

เปิด `http://<ip-เครื่อง>:5000` แล้วตรวจ `/api/stats` ว่า `skipped_fps` = 0

## ★ เกณฑ์ตรวจรับที่ห้ามข้าม

ระบบจะมีค่าก็ต่อเมื่อผ่านทั้ง 4 ข้อนี้ — รายละเอียดเต็มอยู่ใน
[`10-chokepoint-design.md`](docs/10-chokepoint-design.md) หัวข้อ 7

1. **คุณภาพภาพ** — ตัวอักษรบนป้าย ≥ 25 px, มุมเบี่ยง ≤ 30°, รถ ≤ 10 km/h
2. **ทดสอบกลางคืน** — อ่านป้ายจากภาพได้ ≥ 19 จาก 20 คัน หลัง 20:00 น.
3. **เวลาตรงกับ NVR** — ต่างกัน < 2 วินาที ทุกอุปกรณ์
4. **End-to-end กับคนจริง** — เจ้าหน้าที่เอา timestamp จากระบบไปเปิดใน NVR แล้วเจอภาพนั้นจริง

> **ถ้าคุณภาพภาพไม่ผ่าน ห้ามเขียนโค้ดต่อ — ให้กลับไปแก้การติดตั้ง**
> ไม่มีโมเดล AI ตัวไหนกู้ภาพเบลอได้

## ข้อจำกัดที่ต้องแจ้งผู้ใช้

- เห็นเฉพาะจุดคอขวดที่ติดตั้ง **ไม่เห็นความเคลื่อนไหวภายในโกดัง**
- ทางเข้า–ออกที่ไม่ได้ติดกล้องเป็น **จุดบอดถาวร** — ต้องสำรวจให้ครบและบอกผู้ใช้
- ดัชนีอาจเก็บนานกว่าที่ NVR เก็บวิดีโอ — ค้นเจอแต่คลิปอาจถูกลบไปแล้ว
- ผลจาก AI **ไม่ใช่ข้อเท็จจริง** ต้องยืนยันด้วยวิดีโอเสมอ
